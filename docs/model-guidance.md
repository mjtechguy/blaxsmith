# Phase-specific model guidance

Anvil planning, implementation and independent review expose optional model guidance. Choose Preserve allowance, Balanced or Quality first and indicate ambiguity, multiple components, high consequences or weak automated checks. The panel explains its suggested capability group and effort. Nothing is applied until **Apply suggested model and effort** is clicked; application does not launch work or change quality gates.

The mapping is a transparent Anvil heuristic. It is not an evaluated ranking or a promise that stronger models prevent errors. Exact connected model IDs are matched to dated provider capability descriptions. Team recommendations and defaults break ties only within the requested group. Unsupported effort is not invented: the panel uses reported supported effort or a supported default, otherwise preserves the explicit setting. Other providers and custom endpoints remain manually selectable. Missing capability, price, usage and quota information is labelled unknown.

Initial source review: 2026-09-26. The official descriptions position [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna) for efficient focused work, [GPT-6 Sol](https://developers.openai.com/api/docs/models/gpt-6-sol) for complex coding/agentic tasks and [GPT-6 Astra](https://developers.openai.com/api/docs/models/gpt-6-astra) for the hardest extended tasks. Suggestions from this curated set expire after 90 days without a source review. Connection catalog timestamps are shown separately; a listing is not runtime approval, current grant availability or remaining subscription allowance.

The phase picker reads project-selected and owned personal invocation grants, including for members who cannot manage organization connections. Only granted models are listed. Selecting a model pins its connection ID along with model and effort. The frozen recipe profile records `connection`; planning/execution API options use `connection_id`. A missing, revoked or inaccessible pinned account fails instead of switching to another billing account. Clearing the account explicitly restores personal-first/project routing. Manual exact model IDs remain available. Runtime approval, delivery policy, harness support and live access are still checked at launch and reservation; a grant is not a quota guarantee.

To qualify advice, compare exact model, effort, harness/version, instructions, tools and task fixtures. Record accepted outcomes, repair attempts, elapsed time and observed cost across all attempts. Do not turn API price lists into subscription allowance estimates or infer model quality from names. Broader provider/benchmark coverage and observed usage are not implemented by this panel.

The real browser E2E changes preferences/risk, verifies suggestions do not alter settings automatically, applies both capability groups, checks supported effort, and confirms quality gates stay unchanged. It uses catalog metadata without credentials or paid calls; it does not claim empirical model quality validation.

`GetProjectModelOptions(project_id, harness)` exposes the same non-secret choices through the browser, machine API and MCP (`project.read`). Responses include connection ID, label, provider, ownership/authentication category, granted model metadata, catalog timestamp and catalog errors. Personal connections belonging to another user and inactive/expired/revoked grants are excluded. No provider credentials are read.
